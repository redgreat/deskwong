## 2. 每里程碑的「完成定义（DoD）」

1. 对应 `plan/` 任务全部完成。
2. 对应 `rules/` 验收标准全部通过并记录。
3. 文档状态更新为「已完成」，变更记录已写。
4. 代码已提交本地 git（不推送远程，除非批准）。
5. 已知问题登记为 issue/待办，不阻塞后续里程碑。

## 3. 综合验收清单（最终交付）

- [ ] 主屏：月历/农历/节假日/周末/天气/温湿度/倒计时/工时摘要/AI 用量 全部正确且稳定
- [ ] 配置后台：登录鉴权 + 全量配置 + 管理操作可用
- [ ] 工时与提醒：拉取展示 + 三类提醒按规则触发
- [ ] RaceBox：按键采集 → 解析 → MQTT 上传 → 擦除全链路可靠
- [ ] AI 用量：DeepSeek/Codex（及扩展 Mimo）用量展示正确
- [ ] 扩展：电量/录音/语音 + 圈选 P2 功能可用
- [ ] OTA：可升级固件
- [ ] 稳定性：7×24 连续运行无崩溃/内存泄漏（观察）
- [ ] 安全：密钥不入库、接口脱敏、日志脱敏

## 4. 测试与联调策略

- 外部服务（天气/工时/AI 用量/云语音/MQTT Broker）一律先用 `mock/` 本地模拟，避免打真实服务。
- 硬件链路（屏幕/RTC/SHTC3/音频/TF/按键）分模块单测，再集成。
- 时间敏感功能（提醒）用「可注入时间源」测试，模拟 08:25/17:00/17:35 边界。
- RaceBox 先用 mock 蓝牙外设 + 真实设备抓包双向核对。

## 5. 交付物清单

1. `firmware/`：可烧录固件源码 + 分区表。
2. `web/`：Svelte 配置后台源码 + 构建产物。
3. `mock/`：外部服务 mock（天气/工时/AI 用量/MQTT Broker）。
4. `tools/`：烧录脚本、节假日数据导入工具、RaceBox 数据校验工具。
5. `doc/`：完整需求与计划（本目录）。
6. 使用说明：烧录、配置、按键说明。
