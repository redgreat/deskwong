## 1. 总体目标

把 ESP32-S3-RLCD-4.2 打造成一款桌面摆件，交付以下能力（按优先级）：

| 优先级 | 模块 | 一句话目标 |
| --- | --- | --- |
| P0 | 日历主屏 | 中文农历月历 + 节假日/周末 + 天气 + 温湿度 + 倒计时 + 工时摘要 + AI 用量 |
| P0 | 配置后台 | Svelte 网页配置，账号密码登录，管理所有可配置项 |
| P0 | 工时与提醒 | 读 PingCode（经用户 API）工时 + 三类本地提醒 |
| P1 | RaceBox 采集 | 按键触发 BLE 下载/解析/MQTT 上传/擦除 |
| P1 | AI 用量展示 | DeepSeek 今日 Token、Codex 剩余额度等（预留 Mimo） |
| P1 | 扩展功能 | 充电电量、录音、语音 AI |
| P2 | 扩展功能 | 屏保、番茄钟、待办、纪念日等 |

## 3. 实施顺序与依赖关系

```
M0 环境骨架
 ├─> M1 日历主屏 ──> M3 工时与提醒 / M5 AI用量
 ├─> M2 配置后台 ──> M3 / M4 / M5
 └─> (并行准备) mock 服务：天气/工时/AI用量/MQTT Broker
M4 RaceBox（相对独立，可与 M1/M3 并行）
M5 AI 用量展示 + 扩展功能一期
M6 扩展功能二期 + OTA + 验收
```

## 5. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 农历/节假日数据不准确 | 主屏/提醒错误 | 用权威数据源，支持年度导入更新（D1） |
| 内网无外网 | 天气/AI用量/语音不可用 | 预留内网代理（`server/`）或降级本地显示 |
| RaceBox BLE 协议差异 | 采集失败 | 用真实设备抓包核对协议，先做兼容层 |
| MQTT 依赖自建 Broker | 上传不可用 | 断网/断连落 TF 卡缓冲，重连补发（QoS 1） |
| 电量无 fuel gauge | 电量不准 | 先电压分档，后续外挂 MAX17048（D6） |
| 语音 AI 依赖第三方 | 稳定性/成本 | 复用官方小智方案，保留降级（仅本地录音） |
| ESP32 资源紧张 | 卡顿/内存不足 | LVGL 局部刷新，静态资源放 TF 卡，分区规划 |
