## 1. 目标

在主屏展示**近期使用的 AI 服务的剩余额度 / 整体用量**——首批为 DeepSeek 今日 Token 用量、Codex 剩余额度，未来可平滑扩展小米 Mimo 等，让配额余量一眼可见。

## 2. 功能需求（做什么）

### 2.1 展示内容
- 主屏底部信息区（与天气/倒计时共用轮播）展示各 AI 服务的用量，每条显示「名称 + 指标 + 数值」。
- 首批支持：**DeepSeek（今日 Token）**、**Codex（剩余额度）**；后续扩展 **小米 Mimo** 等。
- 展示项可配置：哪些 provider 显示、顺序、刷新周期。
- 状态着色：`normal`（正常）/ `warning`（告警）/ `exceeded`（用尽或超额）。

### 2.2 AI 用量聚合 API 契约（D9，已定稿）
设备只消费统一结构，由**用户自建聚合 API** 返回（用户负责聚合 DeepSeek/Codex/Mimo 各家的用量）：

```jsonc
// GET {base}/ai/usage
// Header: Authorization: Bearer {token}
// 200 OK
{
  "code": 0,
  "message": "ok",
  "data": {
    "updated_at": "2026-09-06T12:00:00+08:00",
    "providers": [
      {
        "id": "deepseek",
        "name": "DeepSeek",
        "label": "今日 Token",
        "value": 1234567,
        "unit": "tokens",
        "display": "123.5万",        // 设备优先直接展示此文案
        "status": "normal"            // normal | warning | exceeded
      },
      {
        "id": "codex",
        "name": "Codex",
        "label": "剩余额度",
        "value": 450,
        "unit": "credits",
        "display": "450",
        "status": "warning"
      }
    ]
  }
}
```

- 字段约定：
  - `providers[]`：每个 AI 服务一条。
  - `id`：稳定标识（`deepseek` / `codex` / `mimo` / …），设备据此排序与过滤。
  - `name`：展示名。
  - `label`：指标说明（今日 Token / 剩余额度 / 整体用量 …）。
  - `value` + `unit`：数值与单位（格式化兜底用）。
  - `display`：精简展示文案，设备**优先直接显示**，避免在设备端做复杂格式化。
  - `status`：`normal` / `warning` / `exceeded`，控制颜色；可由后端判定，也可由设备按配置阈值判定。
- 错误响应：`{ "code": <非0>, "message": "<原因>" }`。
- 鉴权：请求头 `Authorization: Bearer <token>`；`{base}`/`{token}` 在配置后台设置。
- **扩展性**：未来新增 Mimo 等，后端在 `providers[]` 加一条记录即可，固件无需改动。

### 2.3 刷新与降级
- 刷新周期默认 10 分钟（可配置）。
- 拉取失败：显示「AI 用量不可用」占位，保留上次成功数据。

## 3. 配置项（配置后台）

- AI 用量聚合 API 地址、Token、刷新周期。
- 展示哪些 provider（`id` 白名单）、排序。
- 告警阈值（可选）：若后端不判 `status`，设备按 `value` + 阈值判定 `warning`/`exceeded`。

## 4. 依赖

| 依赖 | 说明 |
| --- | --- |
| AI 用量聚合 API（用户自建，D9） | 需外网/内网可达 |
| 主屏底部信息区 | 见 `rules/01` §2.7 |

## 5. 非功能需求

- 失败不阻塞主屏；单个 provider 异常不影响其他项展示。
- 展示文案以 `display` 优先，设备端不做复杂格式化。

## 6. 验收标准

1. 主屏正确展示 DeepSeek 今日 Token、Codex 剩余额度及状态颜色。
2. 聚合 API 鉴权正确，失败可降级。
3. provider 展示项、顺序、刷新周期可配置并生效。
4. 新增 provider（如 Mimo）无需改固件即可展示。
