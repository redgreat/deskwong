# AI 协作规则

> 本文件是 AI 与开发者进入项目后的唯一规则入口。最近更新：2026-10-01。

## 1. 阅读顺序

1. `AGENTS.md`：仓库级工具、数据库和设备约束。
2. `doc/REQUIREMENTS.md`：整体产品需求与验收目标。
3. `doc/ARCHITECTURE.md`：当前代码结构、数据流和部署边界。
4. `doc/SPECIFICATIONS.md`：接口、二进制、安全、测试和发布规范。
5. `doc/PLAN.md`：当前完成度、遗留项和验收记录。

`doc/` 内只保留以上五个文件，不再建立模块化 `rules/`、`plan/` 或导航 README。需求变化更新 `REQUIREMENTS.md`；实现事实更新 `ARCHITECTURE.md`；协议和工程约束更新 `SPECIFICATIONS.md`；状态变化更新 `PLAN.md`。

## 2. 工作边界

- 先核对需求、协议和当前代码，再实施；代码与文档冲突时必须同步修正文档。
- 未经明确授权不删除业务数据、不改硬件接线、不推送远程、不向外部服务写入真实数据。
- 用户明确要求构建、刷机、发布或真实只读验证时，可在该范围内执行并给出证据。
- 账号、密码、Token、数据库口令、WiFi 密码不得写入源码、Git、命令输出或日志；配置必须加密保存并脱敏回读。
- 工作区已有改动属于用户；只修改任务范围内文件，不覆盖、不回退。

## 3. 完成定义

- 文档：链接有效、术语一致、协议偏移和单位与代码一致。
- 服务：格式化、单元测试、静态检查、真实接口验证（适用时）、镜像清单验证。
- 固件：主机测试、ESP-IDF 构建、刷写哈希、启动日志和真实业务流程分层说明；缺一层就明确标记未验证。
- UI：设计稿必须由当前生产布局代码真实渲染；检查正常、六行月份、空数据和关键弹窗状态。
- 发布：不能以“命令无报错”代替验收；应查询 registry/release 中的最终 tag、digest 和目标架构。

## 4. 测试规则

- 项目自有测试、桩、夹具和预览渲染器统一放在根目录 `test/`；第三方 managed component 自带测试不迁移。
- 新增业务组件必须同时增加正常路径、边界/错误路径和回归测试；无法主机测试的硬件逻辑要提供桩或明确板测步骤。
- 测试不得依赖真实密钥。真实外部服务测试默认跳过，只能通过临时环境变量显式启用，并且只读、脱敏。
- `test/run.ps1` 是 Windows 统一入口；CI 与本地使用相同测试命令。
- 生成物只写入 `build/` 或临时目录，不提交 `.exe`、PGM、缓存或凭据。

## 5. 变更与提交

- 一个提交只包含一个可说明的主题；发布前运行 `git diff --check` 和统一测试入口。
- 版本标签触发服务镜像发布；GHCR 与 Quay 必须分别验证。发布失败不得宣称全部完成。
- 设备端口和外部环境会变化；历史 COM7 仅是已验证记录，每次刷写前重新枚举。

### 需求变更与开发流程

提出新功能需求或修复 BUG 时，必须按以下固定步骤执行：

1. **查看需求文档**：读取 `doc/REQUIREMENTS.md`，理解整体产品需求与验收目标。
2. **更新需求文档**：如果需求有变化，先修改 `doc/REQUIREMENTS.md`，明确新增或变更的需求点。
3. **查看计划**：读取 `doc/PLAN.md`，检查是否与现有计划冲突。如果冲突则调整计划；如果不冲突则新增未完成的计划项。
4. **遵循规范**：查看 `doc/SPECIFICATIONS.md`（协议规范）、`doc/ARCHITECTURE.md`（架构约束）、`doc/AI_RULES.md`（开发规范）等，确保实现符合所有规范。
5. **文档确认**：完成文档修改后，将文档内容展示给用户确认，**必须等用户确认后再执行编码操作**。

**关键约束**：
- 文档修改优先于代码修改，不允许先改代码再补文档。
- 用户确认是编码的前置条件，未经确认不得开始编码。
- 如果需求变更涉及多个文档，需要全部更新后再统一确认。

### 提交备注格式

提交备注必须采用 `英文分类: 中文描述` 的格式，正文分条讲清本次修改内容。

- 前缀必须是英文简写分类，紧跟英文冒号，冒号后空一格写中文描述。
- 分类前缀限定以下取值：

  | 前缀 | 含义 |
  | --- | --- |
  | `feat` | 新功能 |
  | `fix` | 修复缺陷 |
  | `docs` | 文档变更 |
  | `refactor` | 重构（不改变外部行为） |
  | `test` | 测试相关 |
  | `chore` | 构建、脚本、依赖等杂项 |
  | `style` | 格式调整（不影响代码逻辑） |
  | `perf` | 性能优化 |
  | `ci` | CI 配置 |
  | `build` | 构建系统或外部依赖 |

- 首行描述用中文概括本次修改；正文用列表分条说明改了什么、为什么，必须使用中文。
- 示例：

  ```
  chore: 新增服务器侧重部署脚本并精简镜像标签

  - 新增 script/redeploy.sh，支持在部署机上一键全量重部署 deskwong 服务
  - release workflow 的镜像标签精简为 v0.0.x 与 latest 两个
  ```
