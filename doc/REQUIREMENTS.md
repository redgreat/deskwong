# deskwong 整体需求

> 产品需求单一事实来源。状态：实施中；最近更新：2026-10-12。

## 1. 产品目标

基于微雪 ESP32-S3-RLCD-4.2（400×300 单色全反射屏）实现桌面终端，提供月历、农历、天气、室内温湿度、工时、提醒、AI 额度和 RaceBox 轨迹同步，并通过浏览器配置。核心功能离线可降级，单个外部服务失败不得影响主屏和本地提醒。

## 2. 主屏

- 顶部：电量、WiFi/AP、小智服务连接状态、可选的 RaceBox 状态与轨迹点数、当前时间。企微提醒仍按计划弹出并播放提示音，但不再常驻显示闹钟图标；释放出的图标位固定用于小智连接状态。设备后台关闭 RaceBox 同步时，顶栏不得显示 RaceBox 图标、完成标记或当天定位点胶囊；中间区域保持留白，为未来其他外接设备同步状态预留，不移动右侧时间。日历翻页指示在 RaceBox 关闭时使用中间区域左端的固定位置。顶部状态栏内所有可见图标、文字和胶囊必须按同一条水平视觉中心线上下居中；时间不得贴近上边缘或明显高于其他状态项，在线、离线/AP、RaceBox、语音服务成功/失败和日历翻页等动态状态切换后也必须保持居中。电量百分比在 1%~100% 之间变化（含 WiFi/AP 切换）时，电量与网络文本不得顶到小智图标或分隔线，小智图标与网络符号之间至少保留 8px 可见空白；后台「启用语音」关闭时该位置不显示小智图标，也不影响其后元素的位置。
- 左侧：年份、月份、月工时汇总、周一到周日、最多六行日期；每格显示公历、农历和当日工时进度。月工时百分比胶囊必须在顶部工时标题区域内上下居中，与下方总进度条保留清晰间距，不得贴住进度条。
- 今天黑底高亮；周末下划线；节假日/调休状态可区分。
- 右侧：完整农历、室外天气图标/温湿度、SHTC3 室内温湿度，以及最多两个由后台选择的 AI 应用额度。AI 区固定占用右栏底部，不挤压天气和室内传感器；两个应用同时可见，不使用自动轮播。
- 空数据使用稳定占位，不显示错误值；AP 模式显示 `192.168.4.1` 配网入口。
- 400×300 真实屏幕上文字不裁切、关键关系清晰，设计稿与固件实际布局一致。

## 3. 配置后台

- 首次启动开放 `deskwong-setup` AP；之后可通过设备 IP 或 `deskwong.local` 访问。
- WiFi 已配置时长按 BOOT 约 3 秒，设备立即开放 `deskwong-setup` 配网热点：APSTA 共存、不重启、不清除已保存配置；热点激活期间 STA 按 30 秒慢速重试原网络（全速重试的全信道扫描会压制 softAP 信标导致手机搜不到热点）；热点仅本次开机内有效，重启后自动关闭。
- 配网热点供浏览器经 `http://192.168.4.1` 访问配置后台；配网期间保存的 WiFi 配置重启后生效。
- 提供门户代理认证入口：配网热点下访问 `http://192.168.4.1/p/start`，设备经自身 STA 发起探测并跟随门户重定向，把门户页面反向代理到配网热点内（`/p/<host>/...`），扫码/登录等认证动作产生的放行结果落在设备自身的网络身份上；`/p/check` 返回放行探测结果。代理仅支持 HTTP 门户，需登录后台的接口不受影响。
- 账号密码登录，支持修改密码、退出、失败限制；敏感字段只可写入、不可明文回读。登录页的账号输入框初始值必须为空，前端不得硬编码或自动回填出厂默认用户名；用户修改管理员账号后，无需每次先删除旧账号。浏览器自身基于用户授权的密码管理器自动填充不受此限制。
- 配置网络、时区、天气、工时、AI 用量、MQTT、RaceBox、提醒、语音、OTA 和系统操作。
- 后台首页和系统操作区显示当前固件版本；版本采用与 GitHub 标签一致的 `vMAJOR.MINOR.PATCH`。GitHub Release 同时提供用途明确的单文件 Web OTA 镜像和 USB 全量刷机镜像，避免用户在多个裸 `.bin` 中选择。后台只允许上传 deskwong 应用 OTA 镜像，上传前后校验镜像类型、项目名、版本和大小，拒绝 merged/bootloader/partition-table/SPIFFS 等错误文件，并在确认框中展示当前版本与目标版本。
- 天气/工时/AI 网络任务串行调度；保存后即时生效或明确提示需重启。
- 中文响应式界面，危险操作二次确认，保存/失败状态明确。

## 4. 天气、时间与日历

- RTC 保底、NTP 校时，默认 `Asia/Shanghai`。
- 农历使用本地算法；法定节假日和调休数据支持年度更新。
- 天气优先支持和风天气，也支持免密钥 Open-Meteo；失败保留上次成功数据。
- 板载 SHTC3 默认每 60 秒更新室内温湿度。
- 主屏且 RaceBox 未运行时长按 `KEY` 进入日历翻页模式；翻页模式中短按 `KEY` 查看上一个月、短按 `BOOT` 查看下一个月，翻月后加载对应月份的工时缓存并请求该月 `/worktime/summary`。再次长按 `KEY` 或连续 30 秒无翻页操作返回主屏。
- 主屏短按 `BOOT` 打开覆盖大半屏幕的天气黄历弹窗，再次短按关闭；弹窗第一排以今天起连续 7 天为 7 列，第二排以当前小时起连续 7 个预报时次为 7 列。每个无边框的近正方形单元按三层展示“天气图标与阴晴文字 / 温度 / 日期或小时”，两排天气与黄历区之间使用轻量虚线分隔；温度统一使用完整摄氏度符号 `℃`（U+2103），第一排格式为“最高温℃/最低温℃”，第二排格式为“温度℃”，不得再用单独的 `°` 字符制造一个汉字宽度的空隙。温度与日期/小时必须拆成独立文本对象，分别按实际渲染像素宽度在各自 52px 列内水平居中，不得依赖同一个多行标签的文本对齐效果。第三排显示当天较详细的黄历“宜”“忌”，正文固定使用 14px 中文字体、每项最多两行；330px 正文宽度下每行最多容纳 23 个全角字形，超出两行时在第二行末尾显示省略号，不能缩小字体。黄历接口可能返回的全部宜忌词条都必须有中文字形，不得显示方块字。不显示更新时间或关闭提示等右下角小字。数据失败时保留最近一次成功缓存或显示暂无数据。天气排版必须以开发板实屏照片验收，主机预览居中不能代替实屏验收。
- Web 后台提供小时天气、七日天气和黄历请求所需的 API 地址及密钥配置；密钥只可写入、不可明文回读。
- `KEY`/`BOOT` 的模式切换、翻月和弹窗开关均播放简短按键音，不阻塞界面和网络任务。

### 4.1 实体按键优先级与保留行为

- 主屏短按 `KEY` 保留 RaceBox 同步触发；RaceBox 运行期间，短按 `KEY` 保留同步弹窗收起/展开，长按 `KEY` 保留强制取消同步。只有 RaceBox 未运行时，长按 `KEY` 才进入或退出日历翻页模式。
- 上述 RaceBox 按键优先级只在“启用 RaceBox 设备同步”打开时生效。关闭时短按 `KEY` 改为打开/关闭 AI 用量独立页；长按 `KEY` 继续进入/退出日历翻页，日历模式内短按 `KEY` 继续查看上一个月。提醒条可见时短按 `KEY` 仍优先关闭提醒，不能被 AI 页面入口覆盖。
- AI 用量页与天气黄历页互斥：普通主屏短按 `KEY` 打开 AI 用量页时先关闭天气黄历页；短按 `BOOT` 打开天气黄历页时先关闭 AI 用量页。任一独立页显示时，再按其对应按键关闭；进入日历翻页模式时关闭两个独立页。
- 天气黄历弹窗显示时，短按 `BOOT` 只关闭弹窗；日历翻页模式中，短按 `BOOT` 只翻到下一个月；普通主屏中，短按 `BOOT` 才打开天气黄历弹窗。
- `PWR` 保留硬件行为：短按上电、长按断电，固件不接管该按键。
- `BOOT` 在设备已正常运行时长按约 3 秒，继续开启 `deskwong-setup` 配网热点；在断电状态按住 `BOOT` 再按 `PWR` 上电，继续进入 ESP32-S3 ROM 下载模式。运行时功能不得破坏上电采样的刷机入口。

## 5. 工时与提醒

- 设备只消费统一的 `/worktime/summary` 接口；服务端可使用 PingCode 账号密码只读抓取个人工时并按日聚合。
- 主屏显示每日工时、本月已记录小时和应记录小时及百分比。应记录按本月已过天数折算：本月 1 日至今（含今天）的法定工作日数 × 每日标准工时（8 小时），百分比分母取同一口径。例如今天 10 号且本月已有 7 个工作日，则目标为 7×8=56 小时；翻页浏览历史月份时按该月整月法定工作日计。服务端返回整月应收工时或接口失败保留缓存时，设备端仍按当前月的已过工作日折算显示，不出现整月目标冒充当月进度。
- 工作日默认 08:25 提醒签到、17:00 提醒记工时、17:35 提醒签退。提醒到达时本地屏显提醒条，并播放一段约 1 秒的多音提示音乐，其音量与波形幅度和普通按键音完全一致（跟随后台「普通操作音量」）。提醒条按后台配置的停留时长自动消失（企微签到、企微签退、工时记录分别配置，默认各 5 分钟），未自动消失前按 `KEY` 可立即关闭。
- 周末/节假日静默，调休上班日正常提醒；支持免打扰。

## 6. RaceBox

- 设备 Web 后台 RaceBox 区提供“启用 RaceBox 设备同步”开关，默认开启并保持现有逻辑不变。关闭后立即停止后续 BLE 扫描、连接、下载、MQTT 上传、状态音和同步弹窗；若保存时正在同步，应先安全取消当前会话再停用，不擦除 RaceBox 数据，也不删除已保存的 Broker、主题、设备名、锁定设备或自动擦除配置。
- RaceBox 关闭时不执行按日状态维护，不向主屏或小智上下文报告 RaceBox 当天点数/完成状态；历史数据库和设备端已有日状态保留，重新开启后继续按现有逻辑工作。该开关只控制 RaceBox，配置命名与代码边界应允许以后增加其他外接设备同步类型。
- 按键触发：扫描、连接、查询、下载、流式 MQTT 上传、可选擦除、结束。
- 使用 Nordic UART BLE 服务；下载过程中必须显示设备、状态、下载/上传条数、进度、总耗时和速度。
- 新固件只发布 RBX2；MQTT QoS 1。只有批次获得 PUBACK 后才释放缓存或进入擦除。
- 重复同步、MQTT 重投和中断续传不得制造重复轨迹；上传未确认不得擦除设备数据。
- 大数据量不得按总记录数连续分配内存；使用小批量 PSRAM 缓存并及时释放。

## 7. AI 用量

- 支持 ChatGPT/Codex、Devin Desktop（原 Windsurf）、Claude Code、MiMo Desktop 四个 AI 应用；服务端 `/admin` 后台最多选择两个启用，默认保留 ChatGPT/Codex，选择顺序同时决定桌面上下顺序。超过两个时后台必须阻止保存并明确提示，不能由设备静默截断。未选中的另外两个应用必须停止定时轮询、不得发起登录或用量请求，也不得仅因曾经配置过凭据而在后台继续刷新。
- 每个应用按上游真实返回显示最多两个主要额度窗口，不假设所有应用都有相同的“日/周”限制。ChatGPT/Codex 优先显示 5 小时与每周；Devin 优先显示每日与每周；Claude Code、MiMo Desktop 待账号和套餐可用后按真实窗口映射，未确认前不得编造额度、周期或重置规则。
- 右栏底部约 98px 根据选择数量使用两套固定布局：只启用一个应用时保留当前 ChatGPT 用量区的大卡样式、字号、两行额度与完整进度条，只替换应用图标/短名和真实窗口内容，不绘制空白第二卡；启用两个应用时才改为上下两张约 46px 的紧凑卡，每张首行显示应用短名与状态，随后以两条细进度条显示窗口短标签、剩余百分比和短重置时间。两个应用必须同时可读，不使用轮播。
- 单应用大卡必须显示所选应用自己的 1-bit 单色品牌图标：ChatGPT/Codex、Devin Desktop、Claude Code、MiMo Desktop 分别使用可辨识的官方标志轮廓，统一适配当前 24×24 图标位，不能只把四种应用都画成 ChatGPT 图标或纯文字缩写。双应用紧凑卡使用同源的 16×16 简化版本；图标转换必须检查真实墨迹边界和 1-bit 实屏可辨识度，并保留来源与许可说明。
- 新增 AI 用量独立页，沿用天气黄历覆盖层的 380×264 黑白面板语言。页头显示“AI 用量”和数据状态；一个应用时使用单列大视图，展示 32px 品牌图标、应用名、最多两个主要窗口的大号剩余百分比、完整进度条、重置时间和数据更新时间；两个应用时使用左右两列，每列显示 24px 图标、应用名和各自最多两个窗口。页面只展示服务端已选择的应用，不轮播未选应用；缓存数据明确标注更新时间，完全无数据时显示“暂无用量数据”。
- 进度统一表示“剩余”，实心越长代表剩余越多；短重置时间优先显示 `HH:MM`，跨日显示 `MM/DD`。上游只返回已用百分比时由聚合服务归一化为剩余百分比；缺少百分比或重置时间时分别显示 `--%`、`--:--`，不得用 0 冒充未知。
- 服务端 `/admin` 后台在“AI 用量”区提供四个应用选择项、拖动或上下按钮排序、每个应用的配置状态、独立刷新频率和认证方式。刷新频率以分钟配置并限制在 1～1440 分钟；调度器只为两个已启用且配置完整的应用建立轮询任务，保存配置后立即重排任务，取消选择后立即停止该应用后续轮询。
- 每个应用支持按实际能力选择认证方式：ChatGPT 可由服务容器只读挂载客户端登录态；Devin 在 Linux Docker 中支持后台填写组织 ID 与只写 Bearer Token，也可显式挂载客户端登录态；MiMo 在 Linux Docker 中支持后台填写只写 OAuth Refresh Token，也可显式挂载客户端登录态；Claude Code 暂保留外部 API。MiMo 刷新凭据发生轮换时必须加密持久化，容器重启后不得退回已失效 Token。不能稳定自动化的账号密码登录不得伪装成已实现，也不得用本地 Token 估算值冒充厂商会员额度。
- 敏感凭据必须加密保存且不可明文回读；密码、Token、Cookie、账号标识不得进入设备响应、日志或缓存。账号字段可脱敏回读，密码和 Token 统一返回 `******`。未完成认证配置的应用显示“待配置”，不能被保存为启用项，也不能占用桌面两个展示名额。
- 设备通过用户自建聚合服务读取统一用量协议。无公开个人订阅 API 时不得把厂商 API Key 当作会员额度替代品，也不得在开发板上直接读取桌面客户端凭据。
- 单个应用异常不影响其他应用和主屏模块；失败保留该应用最近一次成功数据并标记陈旧，完全无缓存时显示稳定占位。

## 8. 音频与扩展

- 电量首期使用 ADC 分档；可选 MAX17048。
- ES7210/ES8311 支持录音与小智语音接入；音频资源互斥，提醒优先于对话和回放。
- 音频音量分两个互不覆盖的配置项：后台「普通操作音量」`system_volume`（0-100，默认 60）是除小智语音外所有声音——按键音、开关机音、RaceBox 状态音和企微签到/签退、工时记录提醒铃声——的直接播放音量，这些声音的音量与波形幅度完全一致（提醒铃声只靠旋律长短和音高组合区分，不额外放大），调到 0 全部静音；后台「智能语音音量」`voice_volume`（0-100，默认 60）只用于小智 TTS 回答。小智会话期间临时切换到小智音量，会话结束或提示音插播后按上下文恢复，不能把全局输出永久改成 100。
- 唤醒词采用 ESP-SR（WakeNet9 `wn9_nihaoxiaozhi_tts`，模型在 `model` 分区）常驻实时监听；
  语音会话期间监听自动暂停（无 AEC，防喇叭自唤醒），会话结束自动恢复。
- 语音触发路径：唤醒词、`POST /api/voice/start|stop` 调试端点；不占用硬件按键。
- BOOT 按键映射维持原版：短按=天气黄历弹窗；按住 ≥3 秒=配网热点（APSTA 共存）。
- 唤醒命中后 1 秒内必须先显示语音弹窗和“连接中”状态，不能因 LVGL 锁暂时繁忙而丢失状态事件；冷连接应分别记录 OTA、WSS/hello、首个回复音频耗时，正常网络下从唤醒到进入聆听目标不超过 8 秒。会话建立后至少支持连续三轮问答，MCP 文本帧与 Opus 音频帧不得并发写坏 WebSocket。连接失败或后台重连时不再用语音弹窗遮挡主屏，只更新顶部小智连接图标并保留脱敏日志。
- WiFi 联网且语音启用后，设备应在后台预取 OTA 下发的 WebSocket 地址/token，并提前建立、保活语音 WebSocket；唤醒热路径只发送 `listen detect/start` 并启动采集，正常网络下目标 1 秒内进入聆听。顶部使用固定的自绘小智/机器人图标：连接成功为白底黑图，连接失败或等待重连为完全相同轮廓的黑底白图反显，语音关闭时隐藏；不得使用音乐符号或另换警告三角形。连接意外关闭时后台退避重连，不弹出整块失败页面。缓存失效、token 过期或后台预连接失败时才回退到完整 OTA+WSS 冷连接。
- 小智角色定位为桌面业务数据专家，不采用儿童、冒险或积分游戏设定。回答优先结合 `{{ dynamic_context }}` 中的工时、AI用量、天气黄历和RaceBox摘要，先给结论再给关键数字；明确数据时间和缺失项，不把缓存或未知值编造成实时数据。声纹只用于称呼和个性化，未知身份仍正常回答。
- 语音弹窗的问题和回答正文使用 14px 中文字体，保持两行截断与可读边距；不得使用当前过小的 10px 对话字体。问题与回答的实际中文墨迹须在各自正文行内上下居中：单行按真实文本高度居中，两行整体居中，不得只固定标签顶部坐标。任意服务端中文回复所需字形继续由独立 GB2312 对话字体覆盖。
- 无 AEC 的普通唤醒及 TTS 后续听统一使用小智协议 `listen start` 的 `auto` 模式，由服务端 VAD 自动判定一句话结束；不得使用需要设备主动发送 `listen stop` 的 `manual` 模式后又持续无限推流。每轮 TTS stop 后重新进入 auto listening，至少支持连续三轮追问。
- auto listening 在连续 30 秒没有收到新的 STT/TTS 时必须主动结束会话、释放麦克风并恢复 WakeNet，不能无限上传静音导致再次喊唤醒词无效；超时退出后后台可重新建立空闲 WSS。
- 后台 OTA/WSS 预连接失败须指数退避（10 秒、30 秒、60 秒、最长 5 分钟），取得有效 STA IPv4 后才允许请求；DNS/TLS 连续失败期间不得以固定 5 秒间隔形成重试风暴，也不得阻塞 UI、天气等其他网络业务。网络恢复后下一次成功连接应清零退避。
- 小智上下文源在每次唤醒构建系统提示词时，能够按当前开发板 `device-id` 读取最近一次只读业务快照，包括：今天及本月工时、ChatGPT/Codex 额度与重置时间、当前天气与今日黄历宜忌、今天 RaceBox 已同步的数据条数。第一阶段采用唤醒时快照，不在一次对话中自动刷新；需要追问最新值时再扩展只读 MCP 工具。
- 上下文源不得从公网直接回连开发板局域网地址，也不得在唤醒热路径临时扇出请求 PingCode、天气、AI 或 RaceBox 数据库。开发板在对应数据刷新成功、RaceBox 同步状态变化及低频兜底周期到达时，把内存/本地缓存中的摘要合并上报到 deskwong 服务；服务端按设备保存最后快照，并用小智规定的 `GET`、`device-id` 请求头和 `{code,data}` JSON 契约快速返回。
- 上下文必须携带数据观测时间和新鲜度。某模块失败时保留最后成功值并明确标注“数据更新于……”，无可信缓存时省略该项或返回“暂无数据”，不得把旧数据表述为实时结果。接口只提供汇总值，不暴露工时明细、精确轨迹、外部服务 Token 或声纹特征。
- 已有声纹识别链路保持独立，不因上下文功能修改注册、识别或会话鉴权流程。第一阶段上下文按设备隔离；在服务端能够向上下文请求可靠传递已识别说话人身份前，不按声纹返回个人敏感明细。
- 声纹只用于区分说话人和个性化，不作为“仅主人可问答”的授权门禁。已注册且相似度达到阈值时附带匿名 speaker ID；未知、低置信度、有效语音过短或声纹服务异常时按匿名说话人继续普通问答，不得错误绑定到已注册身份。
- 每个已注册说话人的声纹至少使用 3–5 段、每段 3–10 秒的干净近讲样本，覆盖自然音量和轻微距离变化；阈值不得只照搬默认值，应用留出样本和其他家庭成员样本校准，重点降低错误归属。日志只记录匿名 speaker ID、相似度、阈值和归属结果，不记录声纹向量或原始音频。
- 唤醒词命中和说话人识别是两条独立链路：WakeNet 负责低功耗候选唤醒，服务端声纹提供身份标签。固件应支持可配置的 WakeNet 阈值、命中冷却期和候选命中计数；调整阈值前后以真实家庭电视、人声和近讲样本验收，不能以单次成功代替误触发率测试。仅加 VAD 不能过滤“家里其他人在说话”的误唤醒。
- 后台须明确显示 WakeNet 阈值的方向：数值越低越容易唤醒、数值越高越不易误唤醒，并限制在 ESP-SR 支持的 `40–99`。针对“80仍难唤醒”不能只继续改界面数字；须从串口记录实际生效阈值和麦克风输入峰值，使用 80、70、60 三档近讲/正常距离样本对比命中率，同时观察家庭环境误唤醒，再确定设备配置，不覆盖用户已保存值。
- 语音必须支持夜间免打扰：配置起止小时（两者相等即关闭该功能，默认 23–7），时段内不监听唤醒词、不预热也不重连小智服务端连接，从而不产生后台会话记录、不播唤醒确认音。长按与网页 `POST /api/voice/start` 手动启动不受该时段限制。免打扰只影响"设备主动听"的通道，不得演变成设备失联。
- 误唤醒防护分三层且都必须可观测：帧能量门限（近静音帧不进模型）、命中冷却（≥10 秒）、夜间免打扰。后台必须能区分"用户真在说话"和"环境噪声误触发"，因此监听日志须同时输出阈值、冷却丢弃数、quiet 帧数与当前免打扰判定。
- 服务端会话记录不得被设备自身的连接行为污染：空闲预热与断线重连都会在服务端各生成一条会话，若用户反映"半夜多出很多自动会话"，必须先查是唤醒误触发还是重连刷出来的——两者的处置完全不同（前者调阈值/免打扰，后者修退避），不得只凭会话条数下结论。
- 多轮追问只在 TTS 播放结束后的短窗口内开放，目标默认 10 秒；窗口内每轮可重新区分说话人，识别失败按匿名处理而不中断问答。超时后必须结束逻辑对话并恢复唤醒词，之后即使底层 WSS 仍保活也要建立新的对话上下文，不得把隔了很久的家庭谈话接到上一次会话。现有 30 秒仅作为异常兜底上限，不再作为正常连续追问窗口。
- 语音延迟必须分段观测，至少记录同一 `session_id/turn_id` 的：唤醒命中、弹窗显示、listen 发送、首个上行音频、语音结束/VAD、STT 返回、声纹完成、上下文 GET、LLM 首 token、TTS 首文本、首个下行音频、开始播放和播放结束。日志输出耗时与状态，不输出 Token、原始录音或完整敏感上下文。
- 热连接目标：唤醒到 listen 发送不超过 300ms；用户说完到 STT 返回不超过 2 秒；STT 到 LLM 首 token 不超过 2 秒；到首段可播放音频不超过 4 秒。声纹与 ASR 并行且不得无界阻塞首答；短预算内无结果则本轮按匿名处理。服务端空闲关闭、DNS/TLS重连、上下文获取、ASR、声纹、LLM和TTS分别超标时必须能从日志直接归因，不能只记录总耗时。
- 录音和语音默认最小采集、最小留存，未经配置不外传。

## 9. 非功能与验收

- 密钥加密存储，日志脱敏；工时、轨迹、录音仅在授权范围内使用。
- 断网和外部 API 故障不导致复位；主屏仍可显示 RTC、本地日历和缓存数据。
- WiFi 断开自动重连日志必须携带原因码及可读短名（如 201 `NO_AP_FOUND` 未扫到 SSID、15/204 密码或握手失败、202/203 认证/关联失败），便于串口或日志远程定位。
- RaceBox 完成证据包含：完整下载、全部 MQTT PUBACK、NVS 保存、`MQTT stopped`、无复位和消费端幂等结果。
- 发布物包含可验证版本、amd64/arm64 服务镜像和固件产物；设备任务需区分“源码完成、构建完成、刷写完成、实机验收完成”。
