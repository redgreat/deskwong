# deskwong 整体需求

> 产品需求单一事实来源。状态：实施中；最近更新：2026-10-02。

## 1. 产品目标

基于微雪 ESP32-S3-RLCD-4.2（400×300 单色全反射屏）实现桌面终端，提供月历、农历、天气、室内温湿度、工时、提醒、AI 额度和 RaceBox 轨迹同步，并通过浏览器配置。核心功能离线可降级，单个外部服务失败不得影响主屏和本地提醒。

## 2. 主屏

- 顶部：电量、WiFi/AP、提醒状态、RaceBox 状态与轨迹点数、当前时间。顶部状态栏内所有可见图标、文字和胶囊必须按同一条水平视觉中心线上下居中；时间不得贴近上边缘或明显高于其他状态项，在线、离线/AP、RaceBox 和日历翻页等动态状态切换后也必须保持居中。
- 左侧：年份、月份、月工时汇总、周一到周日、最多六行日期；每格显示公历、农历和当日工时进度。月工时百分比胶囊必须在顶部工时标题区域内上下居中，与下方总进度条保留清晰间距，不得贴住进度条。
- 今天黑底高亮；周末下划线；节假日/调休状态可区分。
- 右侧：完整农历、室外天气图标/温湿度、SHTC3 室内温湿度、ChatGPT/Codex 5 小时与每周额度重置信息及进度。
- 空数据使用稳定占位，不显示错误值；AP 模式显示 `192.168.4.1` 配网入口。
- 400×300 真实屏幕上文字不裁切、关键关系清晰，设计稿与固件实际布局一致。

## 3. 配置后台

- 首次启动开放 `deskwong-setup` AP；之后可通过设备 IP 或 `deskwong.local` 访问。
- WiFi 已配置时长按 BOOT 约 3 秒，设备立即开放 `deskwong-setup` 配网热点：APSTA 共存、不重启、不清除已保存配置；热点激活期间 STA 按 30 秒慢速重试原网络（全速重试的全信道扫描会压制 softAP 信标导致手机搜不到热点）；热点仅本次开机内有效，重启后自动关闭。
- 配网热点供浏览器经 `http://192.168.4.1` 访问配置后台；配网期间保存的 WiFi 配置重启后生效。
- 提供门户代理认证入口：配网热点下访问 `http://192.168.4.1/p/start`，设备经自身 STA 发起探测并跟随门户重定向，把门户页面反向代理到配网热点内（`/p/<host>/...`），扫码/登录等认证动作产生的放行结果落在设备自身的网络身份上；`/p/check` 返回放行探测结果。代理仅支持 HTTP 门户，需登录后台的接口不受影响。
- 账号密码登录，支持修改密码、退出、失败限制；敏感字段只可写入、不可明文回读。登录页的账号输入框初始值必须为空，前端不得硬编码或自动回填出厂默认用户名；用户修改管理员账号后，无需每次先删除旧账号。浏览器自身基于用户授权的密码管理器自动填充不受此限制。
- 配置网络、时区、天气、工时、AI 用量、MQTT、RaceBox、提醒、语音、OTA 和系统操作。
- 后台首页和系统操作区显示当前固件版本；版本采用与 GitHub 标签一致的 `vMAJOR.MINOR.PATCH`。GitHub Release 同时提供用途明确的单文件 Web OTA 镜像和 USB 全量刷机镜像，避免用户在多个裸 `.bin` 中选择。后台只允许上传 deskwong 应用 OTA 镜像，上传前后校验镜像类型、项目名、版本和大小，拒绝 merged/bootloader/partition-table/SPIFFS 等错误文件，并在确认框中展示当前版本与目标版本。
- 天气/工时/AI 网络任务串行调度；保存后即时生效或明确提示需重启。
- 中文响应式界面，危险操作二次确认，保存/失败状态明确。

## 4. 天气、时间与日历

- RTC 保底、NTP 校时，默认 `Asia/Shanghai`。
- 农历使用本地算法；法定节假日和调休数据支持年度更新。
- 天气优先支持和风天气，也支持免密钥 Open-Meteo；失败保留上次成功数据。
- 板载 SHTC3 默认每 60 秒更新室内温湿度。
- 主屏且 RaceBox 未运行时长按 `KEY` 进入日历翻页模式；翻页模式中短按 `KEY` 查看上一个月、短按 `BOOT` 查看下一个月，翻月后加载对应月份的工时缓存并请求该月 `/worktime/summary`。再次长按 `KEY` 或连续 30 秒无翻页操作返回主屏。
- 主屏短按 `BOOT` 打开覆盖大半屏幕的天气黄历弹窗，再次短按关闭；弹窗第一排以今天起连续 7 天为 7 列，第二排以当前小时起连续 7 个预报时次为 7 列。每个无边框的近正方形单元按三层展示“天气图标与阴晴文字 / 温度 / 日期或小时”，两排天气与黄历区之间使用轻量虚线分隔；温度统一使用完整摄氏度符号 `℃`（U+2103），第一排格式为“最高温℃/最低温℃”，第二排格式为“温度℃”，不得再用单独的 `°` 字符制造一个汉字宽度的空隙。温度与日期/小时必须拆成独立文本对象，分别按实际渲染像素宽度在各自 52px 列内水平居中，不得依赖同一个多行标签的文本对齐效果。第三排显示当天较详细的黄历“宜”“忌”，正文固定使用 14px 中文字体、每项最多两行；330px 正文宽度下每行最多容纳 23 个全角字形，超出两行时在第二行末尾显示省略号，不能缩小字体。黄历接口可能返回的全部宜忌词条都必须有中文字形，不得显示方块字。不显示更新时间或关闭提示等右下角小字。数据失败时保留最近一次成功缓存或显示暂无数据。天气排版必须以开发板实屏照片验收，主机预览居中不能代替实屏验收。
- Web 后台提供小时天气、七日天气和黄历请求所需的 API 地址及密钥配置；密钥只可写入、不可明文回读。
- `KEY`/`BOOT` 的模式切换、翻月和弹窗开关均播放简短按键音，不阻塞界面和网络任务。

### 4.1 实体按键优先级与保留行为

- 主屏短按 `KEY` 保留 RaceBox 同步触发；RaceBox 运行期间，短按 `KEY` 保留同步弹窗收起/展开，长按 `KEY` 保留强制取消同步。只有 RaceBox 未运行时，长按 `KEY` 才进入或退出日历翻页模式。
- 天气黄历弹窗显示时，短按 `BOOT` 只关闭弹窗；日历翻页模式中，短按 `BOOT` 只翻到下一个月；普通主屏中，短按 `BOOT` 才打开天气黄历弹窗。
- `PWR` 保留硬件行为：短按上电、长按断电，固件不接管该按键。
- `BOOT` 在设备已正常运行时长按约 3 秒，继续开启 `deskwong-setup` 配网热点；在断电状态按住 `BOOT` 再按 `PWR` 上电，继续进入 ESP32-S3 ROM 下载模式。运行时功能不得破坏上电采样的刷机入口。

## 5. 工时与提醒

- 设备只消费统一的 `/worktime/summary` 接口；服务端可使用 PingCode 账号密码只读抓取个人工时并按日聚合。
- 主屏显示每日工时、本月已记录/应记录小时和百分比。
- 工作日默认 08:25 提醒签到、17:00 提醒记工时、17:35 提醒签退；只进行本地屏显和一声短提示音。
- 周末/节假日静默，调休上班日正常提醒；支持免打扰。

## 6. RaceBox

- 按键触发：扫描、连接、查询、下载、流式 MQTT 上传、可选擦除、结束。
- 使用 Nordic UART BLE 服务；下载过程中必须显示设备、状态、下载/上传条数、进度、总耗时和速度。
- 新固件只发布 RBX2；MQTT QoS 1。只有批次获得 PUBACK 后才释放缓存或进入擦除。
- 重复同步、MQTT 重投和中断续传不得制造重复轨迹；上传未确认不得擦除设备数据。
- 大数据量不得按总记录数连续分配内存；使用小批量 PSRAM 缓存并及时释放。

## 7. AI 用量

- 设备通过用户自建聚合服务读取 ChatGPT/Codex 5 小时与每周窗口。
- 显示重置时间和剩余额度进度；无公开个人订阅 API 时不得把 OpenAI API Key 当作替代品。
- 单个 provider 异常不影响其他模块，失败保留上次成功数据。

## 8. 音频与扩展

- 电量首期使用 ADC 分档；可选 MAX17048。
- ES7210/ES8311 支持录音与小智语音接入；音频资源互斥，提醒优先于对话和回放。
- 唤醒词采用 ESP-SR（WakeNet9 `wn9_nihaoxiaozhi_tts`，模型在 `model` 分区）常驻实时监听；
  语音会话期间监听自动暂停（无 AEC，防喇叭自唤醒），会话结束自动恢复。
- 语音触发路径：唤醒词、`POST /api/voice/start|stop` 调试端点；不占用硬件按键。
- BOOT 按键映射维持原版：短按=天气黄历弹窗；按住 ≥3 秒=配网热点（APSTA 共存）。
- 唤醒命中后 1 秒内必须先显示语音弹窗和“连接中”状态，不能因 LVGL 锁暂时繁忙而丢失状态事件；冷连接应分别记录 OTA、WSS/hello、首个回复音频耗时，正常网络下从唤醒到进入聆听目标不超过 8 秒。会话建立后至少支持连续三轮问答，MCP 文本帧与 Opus 音频帧不得并发写坏 WebSocket；网络断开时弹窗显示明确错误后再退出，不得无提示隐藏。
- WiFi 联网且语音启用后，设备应在后台预取 OTA 下发的 WebSocket 地址/token，并提前建立、保活语音 WebSocket；唤醒热路径只发送 `listen detect/start` 并启动采集，正常网络下目标 1 秒内进入聆听。连接意外关闭时后台退避重连，弹窗区分“正在唤醒”“服务重连中”“服务不可用”，同时记录不含凭据的 close code/网络错误。缓存失效、token 过期或后台预连接失败时才回退到完整 OTA+WSS 冷连接。
- 语音弹窗的问题和回答正文使用 14px 中文字体，保持两行截断与可读边距；不得使用当前过小的 10px 对话字体。问题与回答的实际中文墨迹须在各自正文行内上下居中：单行按真实文本高度居中，两行整体居中，不得只固定标签顶部坐标。任意服务端中文回复所需字形继续由独立 GB2312 对话字体覆盖。
- 无 AEC 的普通唤醒及 TTS 后续听统一使用小智协议 `listen start` 的 `auto` 模式，由服务端 VAD 自动判定一句话结束；不得使用需要设备主动发送 `listen stop` 的 `manual` 模式后又持续无限推流。每轮 TTS stop 后重新进入 auto listening，至少支持连续三轮追问。
- auto listening 在连续 30 秒没有收到新的 STT/TTS 时必须主动结束会话、释放麦克风并恢复 WakeNet，不能无限上传静音导致再次喊唤醒词无效；超时退出后后台可重新建立空闲 WSS。
- 后台 OTA/WSS 预连接失败须指数退避（10 秒、30 秒、60 秒、最长 5 分钟），取得有效 STA IPv4 后才允许请求；DNS/TLS 连续失败期间不得以固定 5 秒间隔形成重试风暴，也不得阻塞 UI、天气等其他网络业务。网络恢复后下一次成功连接应清零退避。
- 小智上下文源在每次唤醒构建系统提示词时，能够按当前开发板 `device-id` 读取最近一次只读业务快照，包括：今天及本月工时、ChatGPT/Codex 额度与重置时间、当前天气与今日黄历宜忌、今天 RaceBox 已同步的数据条数。第一阶段采用唤醒时快照，不在一次对话中自动刷新；需要追问最新值时再扩展只读 MCP 工具。
- 上下文源不得从公网直接回连开发板局域网地址，也不得在唤醒热路径临时扇出请求 PingCode、天气、AI 或 RaceBox 数据库。开发板在对应数据刷新成功、RaceBox 同步状态变化及低频兜底周期到达时，把内存/本地缓存中的摘要合并上报到 deskwong 服务；服务端按设备保存最后快照，并用小智规定的 `GET`、`device-id` 请求头和 `{code,data}` JSON 契约快速返回。
- 上下文必须携带数据观测时间和新鲜度。某模块失败时保留最后成功值并明确标注“数据更新于……”，无可信缓存时省略该项或返回“暂无数据”，不得把旧数据表述为实时结果。接口只提供汇总值，不暴露工时明细、精确轨迹、外部服务 Token 或声纹特征。
- 已有声纹识别链路保持独立，不因上下文功能修改注册、识别或会话鉴权流程。第一阶段上下文按设备隔离；在服务端能够向上下文请求可靠传递已识别说话人身份前，不按声纹返回个人敏感明细。
- 录音和语音默认最小采集、最小留存，未经配置不外传。

## 9. 非功能与验收

- 密钥加密存储，日志脱敏；工时、轨迹、录音仅在授权范围内使用。
- 断网和外部 API 故障不导致复位；主屏仍可显示 RTC、本地日历和缓存数据。
- WiFi 断开自动重连日志必须携带原因码及可读短名（如 201 `NO_AP_FOUND` 未扫到 SSID、15/204 密码或握手失败、202/203 认证/关联失败），便于串口或日志远程定位。
- RaceBox 完成证据包含：完整下载、全部 MQTT PUBACK、NVS 保存、`MQTT stopped`、无复位和消费端幂等结果。
- 发布物包含可验证版本、amd64/arm64 服务镜像和固件产物；设备任务需区分“源码完成、构建完成、刷写完成、实机验收完成”。
