## 阅读顺序

1. **先读 `AI_RULES.md`**：理解 AI 在本项目中的角色、工作流、路由规则。
2. **再读 `rules/00-通用约定.md`**：理解全项目通用的术语、命名、接口、安全约定。
3. **按需读 `rules/01~06`**：各功能模块的需求规则。
4. **读 `plan/00~08`**：了解如何落地（架构、排期、里程碑、验收）。

## 核心约定（一句话版）

- **需求变更**：直接修改 `rules/` 或 `plan/` 中的文档。
- **AI 协作**：AI 先读 `AI_RULES.md` → 依据路由表定位到指定 `rules/*.md` → 再同步更新对应 `plan/*.md` → 报告变更点，等审核后再动代码。
- **单一事实来源**：功能需求以 `rules/` 为准，实施细节以 `plan/` 为准；代码注释不重复文档内容，只做指针引用。

## 维护约定

| 事项 | 规则 |
| --- | --- |
| 改需求 | 直接编辑 `rules/` 对应模块文档，更新文档头部的「版本/变更记录」 |
| 改方案 | 直接编辑 `plan/` 对应文档，同步更新「状态」与「变更记录」 |
| 新增模块 | 在 `rules/` 新增 `NN-模块名.md`，在 `plan/` 新增对应实施文档，并在 `AI_RULES.md` 路由表和本文档结构中登记 |
| 状态标记 | 计划文档头部用「状态」字段：`草案 / 已评审 / 实施中 / 已完成 / 已废弃` |
