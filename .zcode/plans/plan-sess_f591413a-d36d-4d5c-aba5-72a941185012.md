# ESP-SR 唤醒词 + BOOT 按键重映射 实施计划

## 目标
1. 固件接入 esp-sr（WakeNet9），常驻实时监听唤醒词"你好小智"；喊一声即自动建立语音会话，会话结束后自动回到监听。
2. BOOT 按键重映射：短按=开始/结束语音对话；长按 1~3 秒=天气黄历弹窗（原短按功能迁过去）；按住 ≥3 秒=保持现有的 WiFi AP 配网。

## 关键事实（已探明）
- 板子：S3_RLCD_4_2（ES8311+ES7210），单 I2S 全双工，record 句柄 16k/2ch 常开（audio_service_record_handle），当前只有语音会话的 mic_task 读它。
- 16MB flash 分区表已满（ota_0 4M + ota_1 4M + spiffs 7.875M）；网页内容实测仅 61KB，SPIFFS 可安全缩小。
- esp-sr 2.4.7 官方支持 IDF≥5.0（小智官方固件锁定的同款版本），含 wn9_nihaoxiaozhi（你好小智）唤醒模型。
- 按键用 MultiButton：短按 ~300ms 内、LONG_PRESS_START 在按住 1 秒触发；BOOT 现有 boot_still_held_ms(2000) 辅助判断（main.cpp:433-440）。
- 内部 RAM 紧张（会话期仅剩 ~20KB），但唤醒监听发生在空闲期（无 Opus/TLS 占用），esp-sr 在 S3 上 buffer 主要走 PSRAM。

## 改动清单

### 1. 依赖与分区
- `main/idf_component.yml`：加 `espressif/esp-sr ==2.4.7`（首次 configure 需联网下载 ~170MB 组件+模型）。
- `partitions.csv`：新增 `model, data, nvs, 0x820000, 0x200000`（2MB，仅装唤醒模型绰绰有余）；`spiffs` 缩为 `0x5E0000` @ `0xA20000`，总表仍正好 16MB。app 分区不动，不影响 OTA 槽位。
- `sdkconfig.defaults` + `sdkconfig`：启用 wn9_nihaoxiaozhi 唤醒模型、关闭 MultiNet、AFE 走省内存配置（task stack 尽量 PSRAM；具体 Kconfig 符号以 configure 后实际生成为准）。

### 2. 新增唤醒服务 `components/app_services/voice_wake.c/.h`
- `voice_wake_init(cfg)`：`esp_srmodel_init("model")` → `afe_config_init("MM", models, AFE_TYPE_SR, AFE_MODE_LOW_COST)`（单麦克风取左声道）→ 创建 feed/fetch 两个任务（PSRAM 栈优先，core 0）。
- feed 任务常驻 `esp_codec_dev_read`（30ms 块 480 采样，立体声拆左声道）喂 AFE；fetch 任务等 `WAKENET_DETECTED`。
- 触发动作：提示音 `AUDIO_CUE_START` → `voice_service_start_by_wake()`。
- `voice_wake_suspend(timeout)` / `voice_wake_resume()`：**句柄交接**——暂停时 feed 任务停读 record 句柄并确认停稳，供会话 mic_task 独占；恢复由 VOICE_IDLE 事件触发。
- 生效条件：`voice_enabled && (listen_mode==0 || listen_mode==2) && WiFi 已连接 && 会话 IDLE`。listen_mode 从此不再是摆设。

### 3. `voice_service.c` 配合改造
- 新增 `voice_service_start_by_wake()`：hello 后先发 `{"type":"listen","state":"detect","text":"<voice_wake_word>"}` 再 listen start（对齐小智协议，服务端能统计唤醒来源）。
- `voice_service_start()` 入口先 `voice_wake_suspend()`（所有调用方统一安全），teardown/IDLE 路径 `voice_wake_resume()`。

### 4. `main/main.cpp` 按键重映射
- BOOT 短按（原黄历代码块迁出）：`VOICE_IDLE → voice_service_start()；非 IDLE → voice_service_stop()`，带 cue 音；受 voice_enabled 门控。
- BOOT LONG_PRESS_START（1 秒）：沿用现有 boot_still_held_ms(2000) 轮询——仍按住到 ~3 秒 → WiFi AP（现状保留）；提前松手 → 天气黄历弹窗 toggle（原 main.cpp:532-544 代码块整体迁入）。
- WiFi 连接成功后 `voice_wake_init()`。

### 5. `script/flash.ps1` 适配
- spiffsgen 尺寸 `0x7E0000 → 0x5E0000`；SPIFFS esptool 烧录偏移 `0x820000 → 0xA20000`。srmodels.bin 由 `idf.py flash` 自动烧进 model 分区（esp-sr 托管组件自动注册），无需额外命令，但脚本加一条存在性校验。

### 6. 文档
- `doc/REQUIREMENTS.md` 语音小节补唤醒词与按键映射；`doc/PLAN.md` 实施状态加一条。

## 风险与对策
- **内部 RAM**：唤醒初始化时打日志实测 internal/SPIRAM 余量；不足时切 AFE 更省内存配置（alloc mode 往 PSRAM 倾斜）。唤醒期无 Opus/TLS 压力，判断可过。
- **误唤醒**：会话期间暂停监听（v1 不做打断 TTS 的 barge-in，无 AEC），提示音是正弦波不像语音，风险低。
- **首次构建**：组件管理器下载 esp-sr 较大较慢，属正常。
- **回滚**：分区表回退需按旧偏移重刷 SPIFFS，flash.ps1 改动有注释说明。

## 测试与验收
1. `test/run.ps1` 回归（现有多为宿主侧测试，不受影响）。
2. 构建后确认 srmodels.bin 生成且含 nihaoxiaozhi；`idf.py flash` 三样齐烧（app + srmodels + spiffs）。
3. 上板验收（COM7 串口）：
   - 空闲喊"你好小智"→ 1 秒内日志 WAKENET_DETECTED、提示音、OTA/WS/hello 流程走通；
   - 对话一轮（LLM/TTS 出声），结束后日志显示监听自动恢复；
   - BOOT 短按开/停会话；按住 1~3 秒出黄历；按住 ≥3 秒进 AP；
   - 唤醒初始化时 internal 余量 ≥20KB；关掉 voice_enabled 后无唤醒任务（CPU 静默）。
4. 验收标准写入串口日志检查点，方便以后回归。

## 实施顺序
依赖+分区 → sdkconfig（configure 后钉符号）→ voice_wake 组件 → voice_service 改造 → 按键重映射 → flash.ps1 → 构建+刷机 → 上板联调（需要你配合喊话测试）。
